Scope: the 2020 architecture as specified (hmbc2020.txt; Fig. 6 p.12, Table 1 p.5, Tables 2-3 p.15 re-read from the PDF), tested against its own claims; JANUS column from janus2023.txt + A1 (+ one read of JANUS tmsc.js). Static reading only, nothing run. A1 = recheck/context/reports/A1_dissection.md.
Legend. Attacker: EXT external; USR registered user; ADM CA-Admin/stakeholder admin; MIN/MAJ malicious minority/majority of stakeholders; API Inter-BC API operator; VAL validator/node operator; NET network; INS insider with valid credentials. Demo: SOL = Solidity re-implementation on a local dev chain; PV = ProVerif/Tamarin; TLA = TLA+; MC = Monte-Carlo/queueing; ARG = argument. Size S <=1 person-week (pw), M 1-3, L >3.

## 0. Verification of A1 (secs. 1.2, 2, 4)
Confirmed in text/PDF: Fig. 6 (1) [cert_AX, data_id], (4) [GID, verified attributes, data_id], (5) [GID, data_id], (9)-(10) {C,C1}+trans_hash with "store trans_details on the BC"; Table 3 `requestData` "activated when temporal attributes are verified"; Table 1 "Yes" on all five features plus "All types of queries" with no query mechanism anywhere in the paper. New facts: Table 2 `requestAccess` "First, it triggers the requestLog ... and then calls getUserValidation" (log BEFORE validation); Table 3 `policyEnf` actuator is the PSC although the PSC is on another chain.
Corrections. (i) A1 C7: if every domain has h_d > n_d/2 honest, sum h_d > N/2, so domain-to-PBC majority holds for one-stakeholder-one-vote; the real defects are stake weighting, BFT-style finality needing 2/3, and a PoC with no consensus (ganache). (ii) A1 C8 takes III-D4 "complete transaction details" as the on-chain record; V-B3 says "only the transaction hash is stored in the PBC" - the paper contradicts itself and each reading breaks a different claim (D-1, D-3, C-4). (iii) V-A4 "stored on-chain" vs IV-D KSSC "simulated" in Python: keys are either in replicated state or in an unreplicated service (C-2). (iv) A1 1.2 attributes the rejection of patient approval to I-B; it is Sec. II (Related Work).

## 1. Attack catalogue (26 attacks; fields: attacker | location | attack | claim broken | ack/JANUS | demo | A1)

### A - access flow and registration
**A-1 Unsigned, unfresh request: framing, replay, deniability [MED].** Att: EXT/USR with a victim's cert; NET/API replay. Loc: Fig. 6 (1) "[cert_AX, data_id]"; Table 2 requestAccess input "userCert, data_id"; proof of possession only at registration (III-D2). Attack: no signature, nonce or timestamp covers a request; if it reaches the PBC via the shared user API, msg.sender does not identify A. The reply goes to pk_AX so nothing leaks, but logs carry entries A never made and A's real misuse is deniable (no signature in the log). Breaks: I-A5 accountability; VI "strong integrity guarantees". Ack/JANUS: no; JANUS adds challenge-response + Fabric-signed proposals (A1 N1) - FIXES. Demo: PV injective-agreement model of Fig. 6, S. A1: partly (1.2); consequences NEW.

**A-2 GID is a public bearer value; "proof of possession" and cert-linking unspecified [MED, spec gap].** Att: USR, ADM of a second stakeholder, colluding pair. Loc: III-D2 "A will prove possession of the global identifier GID_A ... included in the new certificate cert_AY"; GID "logged on the PBC"; IV-D GID = Ethereum address; "a certificate refresh can be requested". Attack: a logged value proves nothing unless a GID-key signature is required, and none is specified, nor a Y-side check against the RSC link. A user or complicit Y-admin obtains certs/ABE keys under someone else's GID, or merges two persons under one GID, so Lewko-Waters collusion resistance (one person per GID) reduces to out-of-band authority diligence. Breaks: III-C3 collusion resistance via GID. Ack/JANUS: "out-of-band"; JANUS GID is an org-issued cert attribute (A1 N7) - INHERITS. Demo: Tamarin registration model S-M. A1: extends N7 (mechanism new).

### B - trust anchors, membership, governance
**B-1 Single-signature rewrite of CERT/CRL/TempACL incl. root rotation [HIGH].** Att: ADM (one CA-Admin or one stolen key). Loc: III-D1a "A CA-Admin may independently update any trust anchor"; Table 2 updateTrustAnchors input "new Cert, new CRL, new TempACL"; threshold only for add/remove (III-D1b); TempACL entry = (GID, role, period), no cap or co-signer (III-C6). Attack: (i) add any GID to TempACL_X for any period: with cross-hospital Rule 2 this mints all-patient access through the legitimate channel; (ii) push a new "CERT_X" - a root-key rotation that bypasses the addCA/removeCA threshold; (iii) if the call is not scoped to the caller's stakeholder, publish an empty CRL_Y (un-revoke all). Breaks: V-A2 "resistant to collusions"; Table 1 distributed trust. Ack/JANUS: detection only (V-A5); JANUS enforces own-org scope (read tmsc.js:216-286) but single admin remains (A1 N8) - PARTLY. Demo: SOL, S. A1: N8/GC2; root-rotation bypass and scope question NEW.

**B-2 Rollback, staleness, fork of "latest" CRL/TempACL [MED].** Att: ADM; VAL short reorg; MIN of validators. Loc: III-D linked list "index to the previous block"; TMSC "tracks the blocks that contain the latest indexes"; III-D1c "latest signed list"; no sequence number or nextUpdate. Attack: a valid old signed CRL/TempACL resubmitted as new, or a re-pointed index, resurrects revoked users and expired on-duty entries; revoking blocks are not final (V-B3 "finalized before a block is verified") so a reorg un-revokes; a CRL never expires, so a silent admin leaves the last one valid forever. Breaks: I-A2 "easily revocable"; V-A3; Table 1 revocation. Ack/JANUS: no; JANUS updateTrustAnchors has no version field - INHERITS. Demo: SOL replay of old CRL S; TLA reorg window S. A1: NEW (A1 d is latency only).

**B-3 Membership capture and expulsion; rules inconsistent, quorum unspecified [HIGH].** Att: MAJ of one domain. Loc: III-D1b "consensus of stakeholders in the corresponding domain (e.g. a sufficient number of signatures)"; V-A2 "majority of the relevant domain's stakeholders"; V-B1 "majority of existing stakeholders". Attack: a domain majority adds sham stakeholders that become full PBC voters (dilution), or removes ("revoke CERT_Y") the one hospital that would audit it; the expelled party loses replica, users and voice. No cross-layer veto, join delay, cap or stake rule. Breaks: I-A1 adaptable trust; I-A5 forensics "withstand collusion ... of a significant portion"; Table 1 adaptability. Ack/JANUS: honest majority assumed (V-A1); JANUS quorum round(n/2) (A1 f, N6) - INHERITS, worse. Demo: MC capture probability + TLA S. A1: f/f2/GC4 (dilution); expulsion, audit veto, inconsistency NEW.

**B-4 majorityConsent signatures not bound to an action [LOW-MED, spec gap].** Att: stakeholder/VAL that collected signatures. Loc: Table 2 majorityConsent "Sends and receives signed challenges"; one primitive for addCA, removeCA, retrieveLog. Attack: the signed content (action, target, nonce, expiry) is unspecified; a bare challenge lets a quorum for retrieveLog be replayed for removeCA, or a stale quorum reused. Breaks: V-B1. Ack/JANUS: no; JANUS elections - FIXES. Demo: SOL toy S. A1: NEW.

**B-5 Audit gate dilemma [MED].** Att: MAJ cartel; curious VAL. Loc: Table 2 retrieveLog "Authorities grant access through majority voting", Auditor undefined; log replicated at all PBC nodes (V-A5). Attack: if the vote truly gates reading, a cartel vetoes audits of itself (against I-A5); if every node holds the log in state, the vote protects nothing (see D-3). Breaks: I-A5; III-F-2. Ack/JANUS: Auditor undefined (A1 1.2); JANUS gates at API level (A1 a) - INHERITS. Demo: ARG + SOL state read S. A1: partly; dilemma NEW.

**B-6 "Globally detected policy modification" has no enforcement path [HIGH on the claim].** Att: MAJ of a domain. Loc: V-A5 "not possible for a single domain ... to modify an access policy, without such changes being globally detected"; III-F-2; III-E policy update = domain stakeholders "collaboratively configure the Hospital DBC nodes". Attack: DBC contracts are redeployed on the DBC; the PBC logs only requests passing the PSC, and no function in Tables 2-3 anchors DBC code hashes on the PBC. A domain majority silently rewrites Rule 2 or the KSSC. Breaks: V-A5; Table 1 forensics. Ack/JANUS: "easily detected ... replication" under Raft (J p.24) - INHERITS. Demo: ARG + two-chain SOL S. A1: NEW (A1 f says detect-only).

### C - keys, KSSC, temporal roles
**C-1 Every ABE authority is a universal decryptor; the "System" AND does not constrain it [HIGH].** Att: ADM/compromised key server of ONE stakeholder + any ciphertext leak (backup, DB insider, shared Database API F-2). Loc: III-C4 Rule 2 "isDoctorAtHospital(*) AND onDuty(*)"; III-C5 each stakeholder is "an ABE and ... a certificate authority"; III-E2 Remark "keys for the 'System' role would be created by all ABE key authorities for all their users". Attack: in Lewko-Waters any authority mints K(GID*, attr@X) for a fresh GID*; a cross-hospital policy is an OR over all hospitals' attributes, so X alone satisfies it, and X also mints the System key. X decrypts any Rule-2 ciphertext offline: no PBC request, no log, no TempACL. Breaks: I-A2 bypass avoidance; V-A4 "outside the PBC will not be sufficient"; single point of access. Ack/JANUS: partly assumed (V-A1 "ABE keys ... not compromised"); JANUS adds a domain key SK_H in a BC-side Vault (J p.12) - PARTLY FIXES (needs authority + Vault; Vault admin becomes the universal decryptor, J p.20). Demo: Charm LW11 toy, S. A1: NEW.

**C-2 Contracts cannot keep secrets; temporal keys sit in replicated state; isolation assumed [HIGH, acknowledged].** Att: VAL/node operator of any DBC stakeholder; INS with host access. Loc: V-A4 "temporal ABE keys are the only private keys stored on-chain and their protection relies on the isolation mechanism"; V-A1 operators "cannot bypass isolation and access/alter the blocks"; IV-A namespaces. Attack: Docker separates containers, not a host owner from its own node. Every DBC node executes the KSSC and holds its storage, so each operator reads K(GID, onDuty) for all provisioned GIDs; the "AND long-term key" fallback fails against a doctor-insider or any authority (C-1). If keys sit in an off-chain service the KSSC is an unreplicated trusted component; IV-D says the PoC "simulates" it, in one Kubernetes cluster with one administrator, so cross-organisation isolation was never tested. Breaks: V-A4; I-A3 no trusted key authority. Ack/JANUS: explicit assumption; JANUS moves keys to Vault but trusts K8s + Vault (J p.20) - CHANGES. Demo: SOL/Hardhat: store a key in a contract, read it with getStorageAt from a non-owner node (one-day demo). A1: C6 notes on-chain keys; argument + demo NEW.

**C-3 Revocation illusion: certificate revocation does not recall ABE keys [HIGH].** Att: revoked USR/ex-employee. Loc: III-C6 fn. 2 "Revoking static roles ... by revoking the corresponding user certificate"; keys requested "outside the system"; Table 3 requestData only for temporal attributes; Remark "could be extended". Attack: the CRL stops the PBC step but K(GID, Doctor(X)) is never recalled; for long-term-only policies (Rule 1) the user decrypts offline whenever she gets ciphertext. The KSSC AND is optional and data is "already encrypted" (III-C2), so legacy data cannot be retrofitted without re-encryption. Breaks: Table 1 revocation; I-A3 / V-A4 "efficient ABE key revocation". Ack/JANUS: Remark; JANUS FIXES with the domain-key AND (A1 N2) but moves the on-duty key to the user. Demo: SOL/ARG S. A1: N2 (re-encryption point new).

**C-4 Partial decryptions persisted on replicated ledgers [MED-HIGH, conditional].** Att: VAL/stakeholder; later thief of one long-term key or one MSK. Loc: Fig. 6 (9)-(10) "[{C,C1}, trans_hash]" then "store trans_details on the BC"; Table 3 keystoreLog "Logs the partial decryption details on the Domain BC"; III-D4 "complete transaction details" vs V-B3 "only the transaction hash". Attack: if details include {C,C1}, each accessed record's half-decrypted ciphertext sits on every node forever; later theft of that doctor's long-term key (or authority MSK, C-1) opens everything the user ever pulled, from the ledger alone; erasure impossible. Breaks: GDPR/HIPAA motivation (III-E). Ack/JANUS: no; JANUS uses a PSC private data collection (A1 N9) - PARTLY FIXES. Demo: ARG + SOL S. A1: NEW.

**C-5 KSSC as a free partial-decryption oracle [HIGH].** Att: API/ADM/any account that can call the DBC; USR doctor without on-duty status. Loc: Fig. 6 (5) "[GID, data_id]"; Table 3 requestData input "data_id". Attack: requestData is not bound to any PBC verdict. A doctor without on-duty status has a colluding/compromised relay submit (GID_D, data_id, "onDuty verified"); the KSSC returns the system half for GID_D, D finishes with his own long-term key. No TempACL entry and no PBC log exist. Breaks: I-A2 temporal access; V-A5 "any access request ... logged at the PBC". Ack/JANUS: no; JANUS ACSC/KSSC do no caller attestation (A1 e) - INHERITS. Demo: SOL two-chain toy S. A1: e (oracle mechanics new).

### D - logging, cache, relay, availability
**D-1 Log completeness: grant before log, off-chain cache, finality [HIGH].** Att: API (owns the cache DB in Docker 1); VAL minority (reorg). Loc: IV-B request details held in "cache database inside Docker 1 ... forwards this for finalization"; V-B3 "a transaction can be finalized before a block is verified ... only the transaction hash is stored"; IV-A isolation stops "tampering logs before the storing sequence is concluded". Attack: the reply (~600 ms) is released long before the PBC block (12 s) is final. The API sees both the DBC response and the cache, so it can deliver data and skip or delay finalization, delete cached details (only a hash, if any, is on-chain), or a reorg drops the log tx after the grant; requests that never complete leave no record. Breaks: V-A5 "(successful or not) ... logged"; I-A5; Table 1 forensics. Ack/JANUS: isolation assumed; JANUS nests the log write in requestAccess, rejected requests probably not committed (A1 N4, unverified) - PARTLY INHERITS. Demo: TLA pipeline model (grant => finalised log) with counterexample, M. A1: C8/N4 (hash-vs-details, API-controlled finalisation new).

**D-2 The "fully autonomous" Inter-BC API is a notary [HIGH].** Att: API operator (one stakeholder's Docker 1); VAL of one chain. Loc: Sec. II "closer to the Notary scheme [46], except that our model is fully autonomous: in Notary, a trusted individual or group is assumed"; IV-A API "throttle ... keep the flow constant"; Table 3 policyEnf actuator PSC. Attack: a contract on chain 2 cannot authenticate a caller on chain 1; the relay is the only link and carries no proof, quorum or attestation. It can forge verified attributes (C-5), drop messages (D-1), replay old requests (no nonce in steps 4-5), delay revocations behind requests (E-4), and read all metadata and partial decryptions. Honest stakeholder majority does not bind an off-chain component run by one stakeholder. Breaks: Table 1 distributed trust; Sec. II positioning. Ack/JANUS: no; RabbitMQ relay kept (A1 e) - INHERITS. Demo: SOL relay toy + PV message-authenticity model S. A1: e (notary framing, enumeration new).

**D-3 The log is a surveillance and linkability record [HIGH impact, MED claim].** Att: VAL/stakeholder (insurer, manufacturer, rival). Loc: III-D4/V-A5 every request and registration on a PBC replicated by all; III-D2 GID<->cert link logged; III-F-2 "all access is controlled and logged ... privacy ... preserved". Attack: any PBC node reads who (GID, cert roles), which patient/data_id, when, where; GID reuse links one person across hospital, research and manufacturer roles; the retrieveLog vote is no confidentiality boundary (B-5). Breaks: III-F-2 privacy; GDPR minimisation. Ack/JANUS: no; JANUS logs more (A1 a, a2) - INHERITS. Demo: SOL log dump + synthetic traffic S. A1: a/a2/GC1.

**D-4 Flooding at the single entry point; emergency availability [HIGH].** Att: EXT if the user API is reachable, USR/INS; MIN stalling the PBC. Loc: Table 2 requestAccess "First ... requestLog ... and then ... getUserValidation"; Table 3 accessLog/keystoreLog; IV-A "global, unique entry point" with global throttle. Attack: log precedes validation, so unauthenticated or failing requests still cost replicated PBC writes plus DBC logs; throttling is global (no per-GID quota), so a flood delays emergency clinicians; PBC is a hard dependency and no offline break-glass path exists. Breaks: I-A2 emergency access; V-B2; log bloat. Ack/JANUS: cache "configurable"; JANUS congestion levels, no per-user quota (A1 N5) - PARTLY. Demo: MC queueing S; SOL gas/state growth S. A1: N5 (log-before-validate, starvation, no fallback new).

**D-5 Scalability claim does not follow [MED].** Att: n/a (analysis). Loc: V-B2 "number of PBC nodes will grow linearly ... with the number of users"; V-B3 "1000 t/s ... ~12 s"; IV-C ganache-cli. Attack: every PBC node executes every request, so stakeholders add replication, not capacity; each access causes >= 3 PBC writes. The 1000 t/s comes from ganache (no PoS) and 603 ms excludes the 12 s block time. Breaks: V-B2; "efficient" claims. Ack: "further studies should be made" (V-B3). JANUS: Fabric/Raft, 2-300 requests (A1 N10) - PARTLY. Demo: analytic model + Hardhat TPS/state growth S. A1: C1 partly.

### E - policy, revocation timing, statistics
**E-1 Rule 2 not patient-scoped, cannot be scoped cryptographically, no rate limit [HIGH].** Att: INS on-duty clinician; ADM via B-1. Loc: III-C4 prose "patients under emergency treatment" vs formal `α.onDuty(*) THEN X.allow(α, MHR(β)), ∀MHR(β)∈DB_X`; TempACL entry (GID, role, period); data "already encrypted"; policyEnf input "verified attributes, data_id". Attack: no emergency-case predicate or registry; ciphertext policies are static with no per-patient attribute. onDuty = every record in every hospital at ~600 ms each, through a logged channel (snooping, mass harvesting); no notification or quota replaces the rejected patient approval (Sec. II). Breaks: I-A2 "full access to the medical history of a particular patient". Ack/JANUS: no; JANUS Rule 1 identical, code = shift calendar (A1 b) - INHERITS. Demo: SOL + synthetic traces S-M. A1: C5/b/GC2 (crypto impossibility, rate new).

**E-2 "Statistical" access has no mechanism in record-level ABE [HIGH/MED].** Att: USR researcher/insurer. Loc: III-F-2 "Allow insurance companies to access statistical hospital treatment data. Since all access is controlled and logged ... privacy ... is preserved"; Table 1 "All types of queries". Attack: aggregates need (a) a trusted decrypting aggregator outside the system, (b) pre-computed fixed aggregates, or (c) record decryption by the insurer; logging proves who asked, not that answers do not identify; repeated queries by one GID compose (differencing). Breaks: Table 1 "All types of queries"; III-F-2. Ack/JANUS: no; JANUS ships raw counts (A1 h) - INHERITS. Demo: MC differencing on synthetic counts S. A1: h/GC3 (design-level argument new).

**E-3 Adaptability vs static ciphertext policies [MED].** Att: MAJ; expelled stakeholder. Loc: I-A1 "add a trust authority for a new hospital ... in a flexible but also secure manner"; III-C3 "the encryptor can determine a policy"; V-A3 "modifying the ACSC". Attack: MA-CP-ABE ciphertexts embed authorities' keys at encryption time: new stakeholder Z cannot read old records until all are re-encrypted; removed Y keeps working keys for old ciphertexts (C-1, C-3); loosening ACSC rules does not widen what keys open. No re-encryption protocol. Breaks: Table 1 adaptability; Intro "dynamic changes in policies". Ack/JANUS: no - INHERITS. Demo: Charm toy/ARG S. A1: NEW.

**E-4 TOCTOU: checked at the PBC, used at the DBC [MED].** Att: revoked USR; API delay; flooding accomplice. Loc: Fig. 6 (2)-(3) check vs (4)-(8) use; IV-A throttle; Table 3 policyEnf consumes "verified attributes" with no expiry. Attack: verified attributes carry no validity bound, so a request validated at t0 is honoured whenever delivered; queue delay grows under load; revocation needs an admin tx plus block inclusion (12 s) plus finality (B-2). Flooding (D-4) widens the window. Breaks: I-A2 "easily revocable"; V-A3. Ack/JANUS: cache delay "negligible (2 ms)" at 100 requests; JANUS adds tx-timestamp check (A1 d) - PARTLY. Demo: MC queueing with revocation events S. A1: d (attacker-tunable window new).

### F - data layer, devices
**F-1 Ciphertexts lack authenticity and freshness [HIGH, safety].** Att: DB host/INS with write access; EXT who breached a DB. Loc: III-C2 "full control and responsibility for the proper maintenance of their data"; Fig. 6 (6)-(7) "encrypted data [C]"; III-B users "may need to read or write" but Tables 2-3 have no write path. Attack: nothing on-chain commits to C. A DB can serve another patient's ciphertext, an older allergy/medication version, or a record the attacker encrypted (ABE encryption needs only public parameters, so doctors decrypt it fine). Undetectable by system and log. Breaks: VI "strong integrity guarantees"; I-A5 (covers requests, not data). Ack: data layer outside design. JANUS: no binding (A1 g1) - INHERITS. Demo: SOL commitment toy + Charm injection toy S. A1: g1 (injection, no write path new).

**F-2 One Database API serves all DBCs [LOW-MED].** Att: compromised API/INS. Loc: IV-A "using a single database API for all the DBCs does not pose security issues due to the isolation achieved with the use of dockers". Attack: one component reaches every stakeholder's DB; compromise yields bulk ciphertext of all domains (the leak C-1 turns into plaintext). Breaks: domain autonomy. Ack: asserted safe. JANUS: retained - INHERITS. Demo: ARG. A1: NEW (minor).

**F-3 Firmware: logged but unverified [MED].** Att: manufacturer ADM/INS; stolen signing key. Loc: III-F-1 "upload signed firmware ... pulled by the devices. Since all actions will be logged ..."; V-A2 signing keys outside the system; Maintenance-Admin updates "all medical devices ... for all hospitals". Attack: signature checking is outside the system, so the log proves a push, not its content or that it is not a rollback; one admin role updates a whole fleet with no four-eyes rule. Breaks: I-A5 vigilance. JANUS: code only checks patch status (A1 i). Demo: ARG. A1: i.

### G - consensus assumptions
**G-1 "Honest majority" is the wrong threshold; PoS unspecified and unevaluated [MED].** Att: MIN >= 1/3 (finality) or > 1/2 (reorg, censorship). Loc: V-A1 "majority of its stakeholders are honest"; III-D4 LSC tamper-proof "provided that a majority ... is honest"; IV-C ganache-cli. Attack: accountable-safety PoS/BFT finality needs 2/3 honest (>1/3 can stall, and in a consortium with no slashing finalise conflicting histories); a bare majority lets a minority censor or reorg (B-2, D-1). Stake weighting breaks the domain-to-PBC inference (correction to A1 C7). The evaluated system had no consensus layer. Breaks: V-A5 "Collision resistance". Ack/JANUS: Raft is CFT (J p.24) - CHANGES. Demo: TLA/MC S. A1: C1/C7/f (threshold correction new).

## 3. Ranked top-10 (impact x demonstrability x novelty, 1-3 each)
1. **C-1** 3x3x3: one authority defeats the single-entry claim; Charm toy S; not in A1; JANUS only partly fixes.
2. **C-2** 3x3x2: one-day Hardhat demo reading a "private" key; paper concedes the assumption, the demo and structural argument are the contribution.
3. **D-2** 3x3x2: contradicts the paper's own Sec. II positioning; SOL + PV; JANUS inherits.
4. **D-1** 3x2x2: attacks the flagship forensics claim; TLA counterexample.
5. **B-6** 3x2x3: claim with no enforcement path; cheap two-chain toy.

7. **B-1 (+E-1)** 3x3x2: one admin key gives all-patient access via the legitimate channel.

9. **F-1** 3x2x2: patient-safety integrity, forged-ciphertext injection.
10. **D-4** 3x2x2: log-before-validate ordering, emergency starvation/SPOF.

## 4. What the design gets right
- Cryptographic single-entry idea: the gatekeeper holds only half the keys, so a compromised KSSC alone cannot decrypt (V-A4); JANUS generalises it.
- Temporal roles never leave the system, so expiry needs no re-keying (for KSSC-gated data).
- No global root for credentials or ABE keys; GID-bound collusion resistance in principle.
- Anchors on a replicated ledger as linked lists are tamper-evident; CRL/TempACL decoupled from certificates.
- PBC (identity, log) / DBC (policy, keys) split confines a DBC compromise to its domain's policy.
- Sec. V-A1 states its assumptions explicitly, which makes assumption-by-assumption analysis possible; PoC scale and Docker library staleness are admitted.
- Rejecting per-access patient approval for emergencies (Sec. II) is the right operational constraint.
