## What the checker joins

`evaluation/signing_event_join_v2.py` consumes the published witness JSON-lines
envelope (`hmbc-witness-rpc/v1`) in a capture document and an independently
verified `WitnessEvidence` export. Each captured successful signature reply must
match a verified stored signature by typed digest, signature, type, domain,
witness-set version, key and effect. The output includes the exact signed-history
generation (`seq` for superseded records) and its store-reported ledger
observation. Error replies are counted but are not treated as signing events.

The protocol envelope and response behavior are read from the portable protocol
role's exact candidate `37ca31c80ab9a81956647428435addb1802cb370` on
`origin/agent-1`, `protocol/hmbc_protocol/witness_main.py`. The store observation
contract is read from the same candidate's `protocol/hmbc_protocol/witness_state.py`.
Fixtures are generated by the existing signing/history test helpers; keys and
observations are synthetic.

## Limits

The capture document and its JSON-lines are caller-supplied and unauthenticated;
the helper reports `captureAuthenticated=false` and
`transcriptCompletenessEstablished=false`. It proves only that each captured
successful reply contains a signature valid for the pinned synthetic witness and
has an exact matching record in the separately verified export. It does not prove
that the process emitted every event, that the export contains every SQLite/WAL
record, or that an honest service validated a real ledger proposal before signing.
The matched observation remains store-reported. `verify_native_history` can check
separately supplied raw blocks and death calls, but does not authenticate the RPC
endpoint or provide the missing event/export completeness guarantees. There is no
wall-clock signing-time claim, power-loss claim, or gate result.

This helper is not wired into `evaluation/f_preflight.py` or an F execution runner.
Plan status remains DRAFT; all 32 cases and Gate F remain NOT_RUN; G remains locked.
