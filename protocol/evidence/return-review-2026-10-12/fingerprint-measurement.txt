## Reading
   The fingerprint ignores `profile`, `mutations`, `deployBlock`, TMSC/LSC and every runtime hash. A clean repaired-e run and a mutant-* run on fresh chains are
   indistinguishable to the guard, so a worker state directory reused across them would be accepted. Runs used one NEW state directory per deployment (runner
   rule), so no result was affected; the guard simply does not enforce what its comment says. agent 3's evaluation/worker_evidence.py recomputes the same formula,
   so changing it is an interface change (RFC + agent 3 ACK). NOT changed in this review.
