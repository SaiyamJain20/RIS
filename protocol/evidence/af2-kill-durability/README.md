# Evidence: random SIGKILL durability of the witness store, and the recovery defect it found (agent 2, 2026-11-08)

PAPER-DERIVED RECONSTRUCTION; synthetic signer; one host (Linux, local filesystem); CPython 3.13.12 from the frozen root `uv.lock`, SQLite 3.50.4 (the library behind the venv `sqlite3`; the diagnosis script ran under the same venv); correlated same-model review. **This measures what happens when a process is killed (SIGKILL). It does NOT measure power loss or an OS crash** (the kernel keeps its page cache when a process dies): see the survivor E1 below, which states that limit by experiment.

## The finding (a real defect of mine, fixed in `ca7766a`)
The older crash tests stop the process at NAMED points (`os._exit(77)` through `crash_hook`). `tests/test_witness_state_kill.py` kills a real child with SIGKILL at a RANDOM moment. First run (`first-finding-init-kill-test-failed-trial3.txt`): the init test failed at trial 3 with `STORE_CORRUPT: the database cannot be read: attempt to write a readonly database`. A diagnosis script (`diag-init-kill-hunt.py.txt`) killed 300 initialising children in the first 14 ms: **16 of 300 (5.3%) left a 4096-byte `signing.sqlite` and a `signing.sqlite-journal` (512 bytes) and every later `init_store` refused the directory** (`init-kill-hunt-300-early-kills-16-refused-before-fix.txt`; 122 of the 300 had finished before the kill). Cause: the process died while SQLite was switching the new file to WAL mode and left a HOT ROLLBACK JOURNAL; `_classify` inspects the directory through a `mode=ro` connection, which cannot roll a journal back (SQLITE_READONLY_ROLLBACK), and the error was mapped to STORE_CORRUPT. A witness killed in its first milliseconds could never start there again without someone deleting the directory. SUCCESSOR-WIRE section 5 says an interrupted initialisation is completed by the next `init_store`.

## The fix
`witness_state._classify` retries ONCE after `_recover(db)` (a read-write connection; SQLite rolls the hot journal back, restoring the pre-transaction pages: no logical content changes) **only** when the directory has NO `INITIALIZED` marker (nothing was ever signed) **and** the read-only error carries the READONLY error class. An initialised store is never repaired by the inspection (it is refused as before, byte for byte unchanged); a corrupt file is still refused.

## What the invariants are (`violations()` in the test file)
I1 every reply the child had printed (a complete line, printed only after `sign` returned) is in the store with the same signature; I2 at most one record is committed without its reply (the request in flight); I3 each key is pinned to one effect, **a pin never exists without a live digest, and the observation baseline is that of the newest record**; I4 the store reopens (integrity check, no fault) and every live stored digest re-signs to the same signature; I5 an interrupted initialisation is completed or refused with a closed reason by the next `init_store`, and the completed store signs. A positive control (a child that replies from inside the transaction, i.e. BEFORE the commit) is caught by I1 (`test_the_harness_flags_a_reply_that_leaves_before_the_commit`).

## Limits, plainly
SIGKILL only: no power loss, no OS crash, no disk error; `synchronous=FULL` is not exercised (E1 survives by design). The kill moments are random, not exhaustive: 300 trials per test show no violation, they do not prove none exists. One host, one filesystem, one SQLite version (3.50.4; agent 3 reports 3.47.2 on its host). Only the witness store is covered, not the worker store and not a multi-process interleaving. Marker-present stores with a hot ROLLBACK journal are refused, not repaired, by design (and the case cannot arise from this module, which keeps its stores in WAL mode). Mutants are single-site edits by the same model family that wrote the code.
